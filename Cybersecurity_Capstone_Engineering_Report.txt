2. TECHNICAL CONTROLS DEPLOYED & LOGGING TELEMETRY
--------------------------------------------------------------------------------
Our security operations engineering team successfully established a three-tier 
defensive framework to achieve complete environment visibility:

* CONTROL A: Decentralized EDR Agent Integration (Wazuh Grid)
  A host-based monitoring agent was deployed on the attack and staging node 
  (kali-agent-02-box). The endpoint configuration file (ossec.conf) was modified 
  to actively harvest user execution histories (.bash_history) and track host 
  privilege escalation prompts (sudo session hooks) in real time.

* CONTROL B: SIEM Log Aggregation Pipeline (Splunk Enterprise)
  Engineered a centralized data pipeline utilizing custom Splunk Ingestion 
  modules. Raw JSON telemetry data and security events generated by the EDR layer 
  are forwarded across secure sockets, enabling real-time timeline auditing.

* CONTROL C: Telemetry Optimization & Alert Tuning
  Developed custom XML signature rules (local_rules.xml) nested within the 
  manager's core architecture. Benign Level 7 system check false positives 
  (such as trusted repository adjustments to /usr/bin/diff) are systematically 
  downgraded to prevent alert fatigue, ensuring high-priority logs remain clear.

3. REGULATORY COMPLIANCE FRAMEWORK MAPPING
--------------------------------------------------------------------------------
The technical controls listed above correspond directly with the mandatory 
safeguards required by international auditing boards:

A. HIPAA SECURITY RULE COMPLIANCE (HEALTHCARE & PHARMACEUTICAL PRIVACY)
   * Rule Standard: § 164.312(b) - Audit Controls
   * Requirement: Implement hardware, software, and/or procedural mechanisms 
     that record and examine activity in systems that contain or use electronic 
     protected health information.
   * Engineering Proof: Our EDR agent logs every terminal command, shell access 
     attempt, and root privilege alteration directly down the logging pipeline, 
     creating an unalterable audit trail for corporate compliance inspectors.

B. SOC 2 TYPE II COMPLIANCE (TRUST SERVICES CRITERIA FOR SECURITY)
   * Trust Criterion: CC7.2 - Security Monitoring & Incident Triage
   * Requirement: The entity monitors the infrastructure and software for 
     anomalies, out-of-bounds administrative behaviors, and potential indicators 
     of unauthorized system modifications.
   * Engineering Proof: The integration between our Wazuh Agent monitors and the 
     central Splunk SIEM dashboard captures active network fuzzing footprints and 
     host anomalies instantly, allowing analysts to perform instant triage.

C. ISO/IEC 27001:2022 COMPLIANCE (INTERNATIONAL SECURITY STANDARDS)
   * Security Control: Annex A.12.4.1 - Event Logging
   * Requirement: Logging facilities tracking system exceptions, administrative 
     modifications, and active errors must be securely generated and maintained.
   * Engineering Proof: Log aggregation handles automated parsing of host records 
     into permanent JSON streams within the Splunk repository, preventing local 
     log deletion or tamper overrides by malicious actors.

4. ENGINEERING RECOMMENDATIONS FOR SYSTEM HARDENING
--------------------------------------------------------------------------------
During perimeter discovery scanning phases, our team flagged a complete absence 
of transport and web framing security layers on the target web node. To eliminate 
risks associated with Web Cache Deception and request smuggling, the client must 
inject the following Nginx gateway hardening headers immediately:

    add_header Content-Security-Policy "default-src 'self';" always;
    add_header Strict-Transport-Security "max-age=63072000; includeSubDomains;" always;
    add_header X-Frame-Options "DENY" always;
    add_header X-Content-Type-Options "nosniff" always;
